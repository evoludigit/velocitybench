## Reads — FraiseQL still leads; one genuine gain
Raw FraiseQL reads rose ~+45–125% vs the July-07 baseline, but so did every engine (faster host). Against the
stable PostGraphile yardstick the ratio is flat — except Q3:

| Scenario | fraiseql-tv / PostGraphile (now) | (Jul-07) | shift |
|---|--:|--:|--:|
| Q1 | 3.10× | 3.12× | ~flat |
| Q2b | 3.39× | 3.21× | +6% |
| T1 | 2.72× | 2.44× | +11% |
| **Q3 (comments+author+post)** | **4.58×** | **2.73×** | **+68%** |

Q3 genuinely improved — the lean `tv_comment` drops the embedded post body + nested author, making the deepest
nested read materially cheaper.

## Writes — a real, large gain; still not "fastest write"
The multi-hop column-aware refresh cut the `updateUser(bio)` cascade fan-out ~110 → ~11 rows:

| | M1 (updateUser bio) | MC1 (consistency cycle) |
|---|--:|--:|
| fraiseql-tv now | **1,113 RPS** (p99 ~190 ms) | **1,103 cyc/s** |
| fraiseql-tv Jul-07 | 89 | 89 |
| ratio vs PostGraphile: now / Jul | **0.38× / 0.04×** (+850%) | **0.81× / 0.09×** |

**Honest scope:**
- M1 write ranking (this run): **async-graphql 9,408** (write-heavy winner) · mercurius 4,027 · actix 3,183 ·
  postgraphile 2,967 · apollo 2,544 · hasura 1,856 · strawberry 1,262 · **fraiseql ~1,113 (slowest measured)**.
  FraiseQL closed a ~30–100× gap to ~1.1–8.5×, but its integrated cascade write is **still last** — not fastest.
- Write **tail latency** stays high (p99 ~190 ms vs 20–30 ms for peers) — the cost of recomputing ~11 rows/write.
- A `username` edit still fans out ~61 rows (~5× the bio cost); M1 measures the cheap bio path.
- **MC1 is the strongest honest angle:** FraiseQL reaches consistent state at 0.81× PostGraphile's cycle rate
  with half the HTTP round-trips and zero stale reads (1 request returns mutation + cascade vs 2 serial requests).
- **async-graphql is the correct write-heavy pick** — the site's workload selector points there, not at FraiseQL.
